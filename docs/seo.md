# SEO — what is done, and what it can honestly buy

Search tags are generated, not hand-written. `tools/build_seo.py` owns the title,
description and every head tag for all nine pages; `tests/test_seo.py` (147 checks) proves the
result. Run `python tools/build_seo.py` after adding a page, and `--check` in CI to catch drift.

---

## 1. The honest expectation

**Ranking for the bare phrase "quantum ascent" is not a realistic goal.** That name is already
held by established commercial sites, several with exact-match domains:

| Who | Domain |
|---|---|
| Quantum Ascent Group (consultancy) | `quantumascentgroup.com` |
| Quantum Ascent Advisors (aerospace) | `qu-aa.com` |
| JP Quantum Ascent (MetaTrader robot) | mql5.com listing |
| Quantum Ascend (trading education) | `quantumascend.org` |

Outranking a five-year-old business on its own brand name is a backlink and authority problem,
not a meta-tag problem. No amount of on-page work fixes it.

**What on-page work does buy**, and what this delivers:

- **Indexation.** Every page is discoverable, crawlable and canonical. Without a sitemap and
  canonicals, five of the six basecamps would never have been indexed at all (see §4).
- **Presentation.** You control the title, the snippet, and the social card. This is most of
  the click-through rate on results you already rank for.
- **Eligibility for rich results.** FAQ accordions, course cards, breadcrumbs.
- **Long-tail wins.** Descriptive queries where a small, genuinely good page can beat a big
  vague one.

### Queries actually worth targeting

These are what the titles and descriptions are written for:

- interactive quantum computing course · learn quantum computing by doing
- quantum computing myths · "qubit 0 and 1 at the same time" wrong
- can entanglement send information faster than light
- quantum circuit simulator in browser · qubit simulator no install
- QAOA Max-Cut tutorial · variational quantum eigensolver beginner
- Bloch sphere interactive · quantum computing course no maths background

The Myth Autopsy is the strongest asset here: those are real questions people type, the page
answers them better than most, and it now ships `FAQPage` schema.

### Brand disambiguation

Every title contains "Quantum Ascent" **plus** a quantum-computing word. That is deliberate: it
teaches Google that this particular Quantum Ascent is about quantum computing, not consulting,
which is how you eventually win the brand query for the audience that wants you.

## 2. What ships on every page

| Tag | Why |
|---|---|
| `<title>`, `<meta description>` | Unique per page; length-checked (≤65 / ≤165) so neither truncates |
| `<link rel=canonical>` | Absolute; consolidates duplicates and query-string variants |
| `<meta robots>` | `index, follow` + `max-image-preview:large` for bigger thumbnails |
| Open Graph (8 tags) | LinkedIn, WhatsApp, Slack, Discord, Facebook previews |
| Twitter `summary_large_image` | X previews |
| Favicon (`.ico`, `.svg`), apple-touch-icon | Brand recognition in tabs, bookmarks, home screens |
| `theme-color` | Mobile browser chrome matches the brand green |
| `preconnect` / `dns-prefetch` | Shaves a round trip off the Google Fonts and KaTeX fetches |

Plus `robots.txt`, `sitemap.xml`, and a 1200×630 `og-image.png` generated by
`tools/make_brand_assets.py` from the same logo geometry the site uses.

## 3. Structured data (JSON-LD)

| Page | Schema | Buys |
|---|---|---|
| `index.html` | `WebSite` + `Course` | Course rich result: free, self-paced, prerequisites, what it teaches |
| `ascent.html` | `ItemList` | The six basecamps as an ordered course outline |
| `myths.html` | `FAQPage` | Expandable Q&A directly in results — **the biggest single win here** |
| subpages | `BreadcrumbList` | Path shown instead of a raw URL |

The FAQ block is **generated by parsing `myths.html` itself**, so the schema can never drift
from the visible page — which is also what stops it being flagged as misleading markup.

## 4. The bug worth knowing about

`module.html` and `lab.html` each serve **six logical URLs** from one file via `?id=01…06`.
Google treats each query string as a separate URL but was seeing one identical static document,
so without intervention all six basecamps collapse into a single indexed page — **most of the
site's actual content, invisible.**

Fixed two ways: the sitemap lists all twelve `?id=` URLs explicitly, and both pages carry a
head script that rewrites `canonical` and `og:url` from the current `?id=` before render.

## 5. Adding the site to Google Search Console

1. Go to [search.google.com/search-console](https://search.google.com/search-console) and add a
   **URL prefix** property for `https://quantum-ascent-77617.web.app/`.
2. Verify. The easiest route for Firebase Hosting is the **HTML file** method: download the
   `google*.html` file Google gives you, drop it in `website/`, and run
   `firebase deploy --only hosting`. (The HTML-tag method also works — but do not paste the tag
   into a page by hand, because `tools/build_seo.py` will overwrite the managed block. Add it to
   the generator instead.)
3. Submit the sitemap: **Sitemaps → `sitemap.xml`**.
4. Use **URL Inspection → Request indexing** on `/` and `/myths.html` to prime the crawl.
5. Check **Rich results** after a few days to confirm the Course and FAQ markup validated.

Expect nothing for 3–7 days, and meaningful impression data in 2–4 weeks. Indexing is not
instant and no setting makes it faster.

## 6. The highest-value things still open

Ranked by impact per hour, and none of them are meta tags:

1. **Get a custom domain** (e.g. `quantumascent.dev`). `*.web.app` is a shared subdomain — it
   carries no domain authority of its own and looks provisional. This is the single biggest
   remaining lever, and it also settles the brand-confusion problem.
2. **Earn a handful of real links.** One mention from QWorld, Qiskit's community list, an
   r/QuantumComputing thread, or a university course page is worth more than every tag in this
   document combined.
3. **Publish the pilot numbers** as a short write-up. "We tested a quantum course on 8 beginners
   and here is the pre/post data" is genuinely linkable; a course landing page is not.
4. **Server-render or pre-render the basecamps.** Google renders JavaScript, but it does so on a
   delay and imperfectly. Six static `basecamp-01.html` … `basecamp-06.html` pages with real
   content in the HTML would index faster and rank better than one JS-driven template.
5. **Translate the glossary.** Hindi and Spanish would open large, much less competitive query
   spaces for the same content.

## 7. What is deliberately *not* done

- **No analytics or tracking.** The site collects nothing, which means no Search Console
  behavioural data beyond what Google measures itself. That is a conscious privacy trade.
- **No keyword stuffing.** Descriptions are written to be read by a human deciding whether to
  click, not to hit a density target.
- **Widget pages are crawlable but not in the sitemap.** They are HTML fragments without their
  own descriptions; listing them would spend crawl budget on thin pages. If a widget ever gets
  a proper wrapper page, add it to `PAGES` in `tools/build_seo.py`.
- **No `X-Frame-Options`.** Being embeddable in Canvas and Moodle is a documented feature
  (`docs/educator_guide.md`), so framing stays open on purpose.
